# GitHub 账户信息同步与字段管理 — 需求规格

## 概述

提供一个表单页面，用户输入 GitHub Personal Access Token 后，服务端调用 GitHub `GET /user` API 拉取账户信息并持久化到数据库；同时提供一个受保护的管理页面，管理员可对用户信息表新增/删除自定义字段。

来源文档：`docs/PRD.md`（V1.0，待评审）。

## 用户故事

- 作为普通用户，我想要输入自己的 GitHub Token 并一键同步账户信息，以便系统记录我的 GitHub 资料而无需手动填写。
- 作为普通用户，我想要在 Token 无效、权限不足或 GitHub 服务异常时看到明确提示，以便知道下一步该怎么做。
- 作为管理员，我想要新增自定义字段，以便后续业务扩展用户数据而不需要每次都改代码。
- 作为管理员，我想要删除不再需要的自定义字段（二次确认），以便清理无用数据结构。
- 作为管理员，我想要看到字段的名称、标识、类型、来源和创建时间，以便管理这些元数据。

## 功能需求

1. F-001 Token 输入表单：密码框（默认隐藏）+ 显示/隐藏切换 + 非空校验 + 提交防重入。
2. F-002 提交后清空 Token，不在浏览器任何存储中持久化。
3. F-003 服务端调用 GitHub `GET /user`（`Authorization: Bearer <TOKEN>`），处理有效/无效/权限不足/限流/服务异常/超时六种响应场景。
4. F-004 按 `githubId` 幂等写入 `github_users`：不存在则创建，存在则更新并刷新 `syncedAt`。
5. F-005 同步页展示头像、用户名、姓名、主页、简介、公开仓库数、粉丝数、最近同步时间。
6. F-006 字段管理页：列表展示自定义字段（名称/标识/类型/来源/创建时间/操作）。
7. F-007 新增自定义字段：校验 `key` 格式（小写字母开头，仅含小写字母/数字/下划线）与全局唯一性；类型限定 text/textarea/number/boolean/datetime。
8. F-008 删除自定义字段：二次确认，级联删除关联字段值；系统保留字段禁止新增同名或删除。
9. F-009 字段新增/删除操作写审计日志（操作者、时间、字段标识、操作类型）。
10. F-010 字段管理接口必须鉴权并校验管理员权限，不得暴露为公开接口。

## 非功能需求

- 性能：正常网络下 95% 的同步请求 5 秒内完成；GitHub API 请求超时 ≤10 秒。
- 安全：Token 全链路（传输/使用/日志/存储）不落盘、不写日志、不回传；`Authorization` 头脱敏；同步接口限流；参数化查询 + 服务端 schema 校验。
- 一致性：用户写入、字段删除及关联值删除使用数据库事务。
- 可观测性：记录 requestId、结果状态、耗时、错误码，禁止记录 Token。
- 兼容性：支持当前主流桌面和移动端浏览器。
- 可维护性：Drizzle schema、migration 与数据库实际结构保持一致。

## 验收标准

### 账户同步

- [x] AC-001 输入有效 Token 后，系统获取 GitHub 账户信息并保存到数据库。
- [x] AC-002 页面展示用户名、头像、主页等核心同步结果。
- [x] AC-003 同一 GitHub 用户重复同步不产生重复记录，`syncedAt` 正确更新。
- [x] AC-004 无效/过期/权限不足/被限流 Token 均显示可理解的错误提示。
- [x] AC-005 Token 不出现在数据库、浏览器持久化存储、URL、响应结果或日志中。
- [x] AC-006 GitHub API 或数据库异常时不会误报“同步成功”。

## 依赖

- GitHub REST API：`GET https://api.github.com/user`。
- 项目现有 `packages/db`（Drizzle + PostgreSQL）、`packages/api`（tRPC）、`packages/auth`（better-auth）基础设施。

## 开放问题（继承自 PRD 第 14 节，本轮设计已给出默认方案，待评审确认）

1. 数据库类型：项目已确认使用 PostgreSQL（`packages/db/drizzle.config.ts` dialect: postgresql）。
2. 项目已具备登录系统（better-auth + tRPC `protectedProcedure`），但**没有管理员角色字段**——本规格默认在 `user` 表新增 `role` 列（见 design.md 技术决策），首个管理员账号通过手动 SQL/种子脚本提升，V1.0 不做角色管理 UI。
3. 自定义字段 V1.0 仅管理字段定义，不在本 feature 内做“用户录入字段值”的前端页面（`user_field_values` 表结构预留，写入能力留待后续 feature）。
4. 删除字段默认硬删除 + 审计日志，不支持恢复。
5. V1.0 不保存 Token，不支持定时同步。
6. “新增/删除字段”采用动态字段模型（字段定义表 + 字段值表），不直接对 `github_users` 执行运行时 DDL。
