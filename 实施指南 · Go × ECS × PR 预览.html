一次「生成个人介绍」请求的完整旅程：

  1. 浏览器从 Cloudflare Pages 加载前端（后端地址构建期写死在 JS 里）。
  2. 点击「生成介绍」→ tRPC 调用 POST /trpc/github.generateIntro 打到 API Gateway。
  3. API Gateway 把 HTTP 打包成事件投递给 Lambda（不经过你的 VPC 网关，这是上周课件的重点）。
  4. Lambda 里的新 procedure 不自己干活，作为薄代理请求 http://go-api.hl-aigc.local:8080/intro/<login>——这个域名只在 VPC 内存在，由 Cloud Map 维护的 Route 53 私有托管区解析到 Fargate 任务的内网 IP。这就是作业要求的「CloudMap 链接 lambda 接口」。
  5. Go 服务用迁移过来的 SQL 查 github_users 表（内网直连 Aurora :5432，流量不出 VPC）。
  6. Go 带着资料调 openrouter.ai 生成介绍——私有子网 → NAT → 公网这条路。
  7. 结果原路返回：Go → Lambda → API Gateway → 浏览器，前端展示。

01阶段一 · Go 服务：连库 + AI 生成个人介绍

全部在本地完成。产出：能跑通 /healthz、/profile/:login、/intro/:login 的 Go 服务 + Dockerfile。

1.1安装 Go 环境

brew install go
go version        # 看到 go1.2x 即可

Go 是编译型语言，产物是单个静态二进制——这正是它适合容器/Fargate 的原因：最终镜像可以只有十几 MB。

1.2初始化项目 apps/go-api

mkdir -p apps/go-api && cd apps/go-api
go mod init hl-aigc/go-api
go get github.com/jackc/pgx/v5

pgx 是 Go 生态最主流的 PostgreSQL 驱动，等价于 Node 侧 drizzle 底下的 pg。整个服务只需要这一个第三方依赖，HTTP 路由用 Go 1.22+ 标准库的 ServeMux 就够（支持方法 + 路径参数）。

1.3main.go 完整代码

核心迁移点：Node 侧 db.query.githubUser.findFirst( { where: eq(githubUser.login, x) }) 在 Go 里就是一条参数化 SQL。表名/字段名与 packages/db/src/schema/github-user.ts 完全一致。 

// apps/go-api/main.go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"io"
	"log"
	"net/http"
	"os"
	"time"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

type Profile struct {
	Login       string  `json:"login"`
	Name        *string `json:"name"`
	Company     *string `json:"company"`
	Blog        *string `json:"blog"`
	Location    *string `json:"location"`
	Bio         *string `json:"bio"`
	PublicRepos int     `json:"publicRepos"`
	Followers   int     `json:"followers"`
	Following   int     `json:"following"`
}

var pool *pgxpool.Pool

func main() {
	ctx := context.Background()

	var err error
	pool, err = pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
	if err != nil {
		log.Fatalf("connect db: %v", err)
	}

	// 预览环境的 postgres sidecar 是张白纸 → 启动时自动建表 + 塞演示数据
	if os.Getenv("PREVIEW_SEED") == "1" {
		if err := ensureSchemaAndSeed(ctx); err != nil {
			log.Fatalf("seed: %v", err)
		}
	}

	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, _ *http.Request) {
		_, _ = w.Write([]byte("ok"))
	})
	mux.HandleFunc("GET /profile/{login}", handleProfile)
	mux.HandleFunc("GET /intro/{login}", handleIntro)

	port := os.Getenv("PORT")
	if port == "" {
		port = "8080"
	}
	log.Printf("go-api listening on :%s", port)
	log.Fatal(http.ListenAndServe(":"+port, mux)) // 监听 0.0.0.0，容器内必需
}

// ===== 从 Node (drizzle) 迁移过来的查询 =====
func queryProfile(ctx context.Context, login string) (*Profile, error) {
	row := pool.QueryRow(ctx,
		`SELECT login, name, company, blog, location, bio,
		        public_repos, followers, following
		   FROM github_users WHERE login = $1`, login)
	var p Profile
	err := row.Scan(&p.Login, &p.Name, &p.Company, &p.Blog, &p.Location,
		&p.Bio, &p.PublicRepos, &p.Followers, &p.Following)
	if err == pgx.ErrNoRows {
		return nil, nil
	}
	return &p, err
}

func handleProfile(w http.ResponseWriter, r *http.Request) {
	p, err := queryProfile(r.Context(), r.PathValue("login"))
	if err != nil {
		httpError(w, http.StatusInternalServerError, err)
		return
	}
	if p == nil {
		http.Error(w, `{"error":"user not synced"}`, http.StatusNotFound)
		return
	}
	writeJSON(w, p)
}

func handleIntro(w http.ResponseWriter, r *http.Request) {
	ctx, cancel := context.WithTimeout(r.Context(), 25*time.Second)
	defer cancel()

	p, err := queryProfile(ctx, r.PathValue("login"))
	if err != nil {
		httpError(w, http.StatusInternalServerError, err)
		return
	}
	if p == nil {
		http.Error(w, `{"error":"user not synced"}`, http.StatusNotFound)
		return
	}
	intro, err := generateIntro(ctx, p)
	if err != nil {
		httpError(w, http.StatusBadGateway, err)
		return
	}
	writeJSON(w, map[string]any{"profile": p, "intro": intro})
}

// ===== 调 OpenRouter 生成个人介绍 =====
func generateIntro(ctx context.Context, p *Profile) (string, error) {
	model := os.Getenv("OPENROUTER_MODEL")
	if model == "" {
		model = "openai/gpt-4o-mini"
	}
	profileJSON, _ := json.Marshal(p)
	payload, _ := json.Marshal(map[string]any{
		"model": model,
		"messages": []map[string]string{{
			"role":    "user",
			"content": "根据这份 GitHub 公开资料，用中文写一段 80 字左右的第三人称个人介绍，突出技术特点，不要编造资料里没有的信息：\n" + string(profileJSON),
		}},
	})
	req, err := http.NewRequestWithContext(ctx, http.MethodPost,
		"https://openrouter.ai/api/v1/chat/completions", bytes.NewReader(payload))
	if err != nil {
		return "", err
	}
	req.Header.Set("Authorization", "Bearer "+os.Getenv("OPENROUTER_API_KEY"))
	req.Header.Set("Content-Type", "application/json")

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		return "", err
	}
	defer resp.Body.Close()
	raw, _ := io.ReadAll(resp.Body)
	if resp.StatusCode != http.StatusOK {
		return "", fmt.Errorf("openrouter %d: %s", resp.StatusCode, raw)
	}
	var out struct {
		Choices []struct {
			Message struct {
				Content string `json:"content"`
			} `json:"message"`
		} `json:"choices"`
	}
	if err := json.Unmarshal(raw, &out); err != nil || len(out.Choices) == 0 {
		return "", fmt.Errorf("unexpected openrouter response: %s", raw)
	}
	return out.Choices[0].Message.Content, nil
}

// ===== 预览/本地环境自举：建表 + 演示数据（只含 Go 用到的列） =====

func writeJSON(w http.ResponseWriter, v any) {
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	_ = json.NewEncoder(w).Encode(v)
}

func httpError(w http.ResponseWriter, code int, err error) {
	log.Printf("error: %v", err)
	body, _ := json.Marshal(map[string]string{"error": err.Error()})
	http.Error(w, string(body), code)
}

02阶段二 · 上云：ECR + ECS + Fargate + ALB + Cloud Map → Lambda

2.0重建底座（全手动控制台版，a→f 顺序做）

上周演示完已删栈。底座五块按依赖顺序手动重建：网络 → 安全组 → Aurora → 跳板机 → Lambda + API Gateway。顺序不能倒—— 数据库要放进 VPC 的私有子网，安全组要引用彼此。先决条件：EC2 → 密钥对里有 hl-aigc-bastion（没有就新建同名密钥对，.pem 放 ~/.ssh/ 并 chmod 400）。

NAT 网关让私有子网里的 Lambda / Go 容器能「出去」调 OpenRouter、 拉镜像，但公网「进不来」——这就是私有子网既安全又能联网的原理。NAT 约 $0.045/小时，是底座里最贵的常驻件，作业交完记得按 04 清单删。

验收：public 子网的路由表 0.0.0.0/0 指向 igw；两个 private 子网的路由表指向 nat。

3.1为什么要三个 IAM 角色：信任边界

核心矛盾：PR 里的代码是不可信的（docker build 会执行 PR 改过的 Dockerfile 和源码），但部署又需要高权限。解法是把权限切成三份，让「碰不可信代码的环节」权限最小：

角色① hl-aigc-pr-trigger

谁扮演：GitHub Actions（OIDC）
只能干：StartBuild / BatchGetBuilds 指定项目
比喻：点火钥匙——只能发动，摸不到别的

角色② hl-aigc-codebuild-build

谁扮演：CodeBuild 服务
只能干：推镜像进指定 ECR 仓库 + 写日志
比喻：只会造镜像的工人——它执行不可信代码，所以就算被 PR 恶意代码劫持，最多也只能推个镜像

角色③ hl-aigc-preview-deploy

谁扮演：GitHub Actions（OIDC）的 deploy job
只能干：ECS/ALB 规则/目标组 增删改 + PassRole（仅限任务执行角色）
比喻：持钥匙的部署员——它只执行 main 分支里可信的 workflow 逻辑

再加两道天然防线：fork PR 在 pull_request 事件下拿不到 OIDC 令牌，连角色①都扮演不了；buildspec 内联在 CodeBuild 项目配置里，PR 改仓库里任何文件都影响不了构建脚本本身。

预览任务里注入了 OPENROUTER_API_KEY（低敏、限额）。因为 fork PR 已被排除，能开 PR 的都是同仓协作者，可以接受；若将来向 fork 开放预览，这类密钥必须从预览任务里拿掉。

VPC / 名称 hl-aigc-vpc / hl-aigc-public-b

(c) ACM 通配证书（控制台，Certificate Manager，注意区域必须是 us-east-2）：请求公有证书 → 域名填 *.preview.<你的域名> → DNS 验证 → 把给出的 CNAME 验证记录添加到 Cloudflare（灰云/仅 DNS）→ 几分钟后状态变「已颁发」。

预览域名是二级子域（api-pr-1.preview.域名）。Cloudflare 免费版的通用证书只覆盖一级子域，所以预览记录必须用灰云（仅 DNS），TLS 由 ALB 上的这张 ACM 证书终结——这也是两位同学图里 “CNAME · DNS-only” 的原因。

name: pr-preview
on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  id-token: write
  contents: read
  pull-requests: write

concurrency:
  group: pr-preview-${{ github.event.number }}
  cancel-in-progress: true

env:
  AWS_REGION: us-east-2
  CLUSTER: hl-aigc

jobs:
  build:
    # fork PR 拿不到 OIDC —— 同仓才继续（安全边界①）
    if: github.event.pull_request.head.repo.full_name == github.repository
    runs-on: ubuntu-latest
    steps:
      - name: 扮演角色①（只能点火）
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ vars.AWS_ACCOUNT_ID }}:role/hl-aigc-pr-trigger
          aws-region: ${{ env.AWS_REGION }}
      - name: 触发 CodeBuild 并等待
        run: |
          BUILD_ID=$(aws codebuild start-build \
            --project-name hl-aigc-pr-build \
            --source-version ${{ github.event.pull_request.head.sha }} \
            --environment-variables-override name=IMAGE_TAG,value=pr-${{ github.event.number }},type=PLAINTEXT \
            --query 'build.id' --output text)
          echo "CodeBuild: $BUILD_ID"
          while :; do
            S=$(aws codebuild batch-get-builds --ids "$BUILD_ID" \
                --query 'builds[0].buildStatus' --output text)
            [ "$S" = "IN_PROGRESS" ] || break
            sleep 15
          done
          [ "$S" = "SUCCEEDED" ] || { echo "build failed: $S"; exit 1; }

  deploy:
    needs: build
    runs-on: ubuntu-latest
    env:
      PR: ${{ github.event.number }}
      HOST: api-pr-${{ github.event.number }}.${{ vars.PREVIEW_DOMAIN }}
    steps:
      - uses: actions/checkout@v4   # 读 .aws/preview-taskdef.json
      - name: 扮演角色③（部署员）
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ vars.AWS_ACCOUNT_ID }}:role/hl-aigc-preview-deploy
          aws-region: ${{ env.AWS_REGION }}
      - name: 部署预览环境（任务定义 → 目标组 → ALB 规则 → 服务）
        run: |
          IMAGE="${{ vars.AWS_ACCOUNT_ID }}.dkr.ecr.us-east-2.amazonaws.com/hl-aigc/go-api:pr-$PR"
          sed -e "s|__PR__|$PR|g" -e "s|__IMAGE__|$IMAGE|g" \
              -e "s|__ACCOUNT__|${{ vars.AWS_ACCOUNT_ID }}|g" \
              .aws/preview-taskdef.json > taskdef.json

               --query 'taskDefinition.taskDefinitionArn' --output text)

          TG=$(aws elbv2 create-target-group --name "pr-$PR-go" \
               --protocol HTTP --port 8080 --vpc-id ${{ vars.PREVIEW_VPC_ID }} \
               --target-type ip --health-check-path /healthz \
               --query 'TargetGroups[0].TargetGroupArn' --output text)   # 同名幂等

          aws elbv2 create-rule --listener-arn ${{ vars.PREVIEW_LISTENER_ARN }} \
            --priority $PR \
            --conditions Field=host-header,Values=$HOST \
            --actions Type=forward,TargetGroupArn=$TG 2>/dev/null || true   # 已存在则跳过

          STATUS=$(aws ecs describe-services --cluster $CLUSTER --services "pr-$PR" \
                   --query 'services[0].status' --output text 2>/dev/null || echo MISSING)
          if [ "$STATUS" = "ACTIVE" ]; then
            aws ecs update-service --cluster $CLUSTER --service "pr-$PR" \
              --task-definition "$TD" --force-new-deployment
          else
            aws ecs create-service --cluster $CLUSTER --service-name "pr-$PR" \
              --task-definition "$TD" --desired-count 1 --launch-type FARGATE \
              --network-configuration "awsvpcConfiguration={subnets=[${{ vars.PREVIEW_SUBNETS }}],securityGroups=[${{ vars.PREVIEW_SG }}],assignPublicIp=DISABLED}" \
              --load-balancers "targetGroupArn=$TG,containerName=go-api,containerPort=8080"
          fi
          aws ecs wait services-stable --cluster $CLUSTER --services "pr-$PR"
      - name: Cloudflare DNS（灰云 CNAME，幂等）
        env:
          CF_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}

          API="https://api.cloudflare.com/client/v4/zones/${{ vars.CF_ZONE_ID }}/dns_records"

                | jq -r '.result[0].id // empty')
          BODY=$(jq -nc --arg h "$HOST" --arg t "${{ vars.PREVIEW_ALB_DNS }}" \
                 '{type:"CNAME",name:$h,content:$t,proxied:false,ttl:60}')
          if [ -n "$RID" ]; then
            curl -sf -X PUT "$API/$RID" -H "Authorization: Bearer $CF_TOKEN" \
              -H "Content-Type: application/json" -d "$BODY" > /dev/null
          else
            curl -sf -X POST "$API" -H "Authorization: Bearer $CF_TOKEN" \
              -H "Content-Type: application/json" -d "$BODY" > /dev/null
          fi
      - name: 回写 PR 评论

          gh pr comment $PR --repo ${{ github.repository }} \
            --body "🚀 预览环境已就绪：https://$HOST/healthz ｜ https://$HOST/intro/octocat"

05常见坑速查

  1. ALB 要求 2 个不同 AZ 的子网——上周模板只有 1 个公有子网，预览 ALB 前必须先建公有子网 B（3.2b）。
  2. 任务架构 ≠ 镜像架构：任务定义选了 ARM64 但镜像是 x86（或反过来），任务启动即退，日志里只有 exec format error。
  3. 镜像里没有 CA 证书：alpine 基础镜像调 openrouter HTTPS 报 x509 错误，Dockerfile 里 apk add ca-certificates 不能省。
  4. Go 必须监听 0.0.0.0：写成 127.0.0.1 的话健康检查永远不过。
  5. db-sg 没放行 go-sg：表现为连库超时（安全组静默丢包，不是拒绝）。
  6. 任务卡 PROVISIONING → STOPPED：点开已停止任务看 stopped reason——多半是执行角色缺 ssm:GetParameters（读不到密钥）或拉不到镜像（NAT 被删 / ECR 权限）。
  7. Cloudflare 预览记录必须灰云：免费版通用证书不覆盖二级子域（*.preview.域名），橙云会 TLS 握手失败；TLS 由 ALB 上的 ACM 通配证书终结。
  8. ACM 证书区域必须和 ALB 相同（us-east-2），别习惯性地申请到 us-east-1。
  9. 别用 pull_request_target + checkout PR 代码：那是把密钥递给不可信代码。本方案用 pull_request，fork 天然无 OIDC；构建不可信代码的 CodeBuild 里没有部署权限。
  10. Cloud Map DNS TTL：任务重启的十几秒内 Lambda 可能解析到旧 IP，TTL 设 10 秒缓解；单任务作业场景可接受，生产应走 ALB——答辩加分点。
